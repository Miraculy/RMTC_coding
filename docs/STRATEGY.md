# 第二阶段策略与验证方法

## 输入边界

每场只启动一个本队席位的 C++ 选手节点，其余三个席位由独立对手控制。轮换 A/B/C/D 是分别重开四场，不是四车协同。

决策只使用本队 `/team_X/perception`、公开任务、公开事件和队伍名录。`core.cpp` 不读取文件、不访问网络；地图记忆来自本队可见实体。敌人离开视野后，记录附带观察 Tick，过期后降低或停止使用。短期位置预测只依据连续两帧本队感知中的位移，遇已知墙或越界时放弃预测，不能视为裁判真值。

事件原文由远程 LLM 理解。程序不使用正则、关键词、固定句式或预设日程推导事件参数。原文去重及按协议分开近期公告仅处理消息重复，不产生事件语义。模型输出必须通过场次、坐标、时间区间和参数校验才进入事件状态。

结构被拒绝时，日志只记录固定的 `schema_error` 分类，不回显任意异常文本或原始模型响应。节点可将原始公开请求、模型的上次输出、固定错误代码和最新已验证事件状态交回 LLM 修复；每条公告至多一次、每场至多八次，计入同一成功调用预算，且排在新公告之后。修复仍必须通过原有严格校验，不由本地代码补猜坐标或理解公告语义。调用保持异步，换场后旧请求不能进入新场。

## 本地资源与任务规划

- 资源采集、路径选择和任务执行完全由本地 C++ 算法完成。
- 资源在一场内不会刷新，坐标任务通常可以稍后完成。前期提高有限资源的优先级，临近截止时恢复坐标任务的紧迫性。
- Dijkstra 评估第一段路径，考虑已知障碍、未知区域、占位和模型已解析的事件。每 Tick 只执行一个动作并重新规划。
- 对记忆资源降低过期置信度；依据近期可见敌人的距离估计竞争，但不读取对手感知或隐藏位置。
- 在尚需探索的前期，适当降低长途返回本车出生点附近资源的优先级，以免错过前方的有限资源。这是可被后续观测修正的几何先验，不代表已知那里没有敌人。
- 路线平局用新增观察区域的收益打破，不依赖资源 ID、固定地图坐标或席位字母。
- 对至多 16 个已知候选资源评估三站短路线。第一段采用实际路径成本，后两段采用曼哈顿距离启发式，不能保证全局最优。任务奖励按剩余进度分配，路线中不重复计入已完成部分，资源计分上限也逐站扣减。
- 已到达当前资源或坐标任务格时，将原地存活完成目标的收益计入等待、防御和攻击，避免因只奖励移动而走离目标。
- 采集类型进度只记录可靠下界：连续两帧的本队资源总价值增加，且新位置存在上一帧已观察的对应资源。漏帧或未知资源的增加不伪造类型计数；已完成任务以本队感知中的任务 ID 为准。
- 没有已知资源不代表地图资源已耗尽。尚有大范围未知区域时继续探索，不立刻放弃采集去追敌。
- 探索目标有适度承诺，减少走了几步就改变方向。它仅作用于第二阶段；发现更好的资源目标或目标失效时仍可切换。

以下为受控实验选项，默认关闭，不能把搜索更复杂视为得分必然更高：

- `information_paths` 仅给 Dijkstra 第一条边一个有上限的信息收益，依据实际下一步视野中未观察的格数计算；后续边不重复累计相同的未知区域。
- `race_aware_resources` 从近期合法观测的敌车位置出发，在本队已知墙体上做 BFS，未知格暂按可通行估计。结合连续帧观察的移动方向和记录年龄，软估计竞争；后续资源站按真正的预计到达步数重新降低成功采集概率。没有宣称知道敌车目标或未知障碍。
- `contested_task_resources` 只在前五分之一场次测试公共任务资源的争夺价值：本车已知路径六步内可达、比当前可见敌车的曼哈顿到达下界早1–4步，且资源为最近一帧内观察时，增加公开采集任务每单位分数的三分之一作为机会估值。后续资源站按预计到达步数重新评估。本车已完成任务也不意味着其他车尚未完成；该值不写入任何队伍的计分，不能据此宣称成功阻止某车完成任务。默认关闭。
- `resource_beam` 在前期用最多八步、每层至多 32 条候选的搜索直接比较沿途已知资源采集、任务边际奖励和新增视野。每条路径在自己的位图中对视野去重，模拟采集与可见格均不写回 `World`。已知致命事件会剪枝，搜索只执行第一步。地图超过 4096 格、没有八步内的资源且仍有已知远处资源、或当前目标属于特殊事件时，保留原规划器；第一阶段不使用该搜索。

## 战斗与事件

战斗按移动前位置结算，不能假设移动避开本 Tick 已经命中的攻击。程序比较攻击、防御、移动和等待；达到伤害计分上限后仍保留合法攻击收益，因为有效伤害参与同分比较。

追击目标是可达的射击位置，不是敌人当前占据的格子。移动到射击位置的奖励与采集路线奖励分别标定，避免为了追逐下一格而放弃眼前命中机会。近期重复踏入相同格子会降低移动评分。

连续可见的一份资源消失、且本队当前视野中有敌车站在该格时，可产生短时竞争信号。默认不因这一信号主动发起前期拦截：资源不会因击杀返还，优先继续采集和探索。眼前已可命中的攻击、可能一击收尾和必要防御仍参与动作比较。可显式开启 `early_interception` 恢复旧的两步内拦截，不将信号当作对手得分真值，也不进行无限追逐。

实验选项 `tactical_forecast` 只从本队连续两帧中估计敌车速度，并评估下一 Tick 的射击机会和暴露风险；拦截按本车实际到达步数匹配预测位置，最多外推三步。这是可随时被新感知推翻的启发式，预测不写入已确认地图。普通射线考虑更近机器人（包括保护车）遮挡，障碍不挡普通攻击。尚未由跨地图对照确认整体收益，默认关闭。

模型提供的事件状态用于调整同一个本地规划器：致命事件强规避；非致命伤害按剩余血量储备估值，避免为少量 HP 放弃不可再生资源；幻术只反转移动命令；堡垒按战斗后驻留计算，攻击和防御也可累计驻留。效果推断有漏帧或不完整证据时保持保守。

DeepSeek 测试显式关闭思考。正式比赛保留主办方网关与本场席位令牌配置。直连 DeepSeek 的成功记录不等于正式网关审计资格，正式任务分仍须满足赛事规则。

## 可复现评估

用户已授权测试时同时运行四辆车。`--opponents self`启动四个独立进程，按本席位合法接口获取消息，不共享观察或决策；支持一辆候选对三辆基线、两辆候选与两辆基线的席位轮换，详见[SELFPLAY.md](SELFPLAY.md)。正式入口仍仅控制自己的一个席位。

2026-10-22 用户补充正式 AI 反馈在事件公告后、生效前返回。后续优化按可提前行动设计，但不假设固定提前量或解析必然正确。24 场逐 Tick 审计、正常事件提前量、目标往返复现及下一步方案见 [TICK_REVIEW.md](TICK_REVIEW.md)；该复盘本身未改变参赛默认行为。

测试脚本 `tools/strategy_eval.py` 在独立的 ROS 公共域、内部域和 HTTP 端口启动练习裁判。裁判配置与赛后观赛比分仅供测试驱动部署和评估，不输入选手程序。不得把该测试驱动作为参赛进程运行。

脚本启动时复制并计算选手二进制 SHA-256，整批场次使用同一快照，避免中途重编译污染对照。每场保留配置、完整最终状态、本队合法观测日志与汇总，输出到已忽略的 `test-results/`。

`--repetitions N` 可对每个地图和席位重复 N 次，重复场使用独立日志目录；不可用重复席位名称代替。整批正常结束、裁判进程关闭后，将裁判的 JSONL 轨迹无损压缩为 `.jsonl.gz`；配置、比分、冻结程序和本队日志保留原格式。失败场的日志不自动压缩，便于诊断。

示例在已经加载 ROS 2 的终端执行，路径和域按本机环境替换：

```bash
python3 tools/strategy_eval.py \
  --judge-root /path/to/rmtc_practice \
  --label local-eval --variants default,map301,map779 \
  --seats A,B,C,D --no-events --domain 48 --port 8083
```

场景包括：

- `default`：练习包原始地图。
- `shuffle<seed>`：重排资源位置，保持原地图尺寸与障碍。
- `map<seed>`：同时改变尺寸、连通障碍、出生位置与席位映射、资源和公开任务坐标。种子只供测试驱动使用，不传给选手。
- `interior<seed>`：同样改变尺寸、连通障碍、资源和任务点，出生点从地图内部随机选择并保持一定距离，用于检查策略是否依赖四角出生。没有资源均衡约束，保留明显不利的出生条件。
- `map<seed>-illusion`、`interior<seed>-illusion`：显式压力场，在上述地图中加入Tick1公告、12Tick后生效、持续50Tick的全图幻术，用于检验事件理解增益。强度采用v1.1标准，区域和提前量是测试条件，不能当成正式赛场假设；两组须真实调用模型、仅切换解释采用。旧版40Tick场景以各批次保存的config.json为准。
- `default-standard`、`map<seed>-standard`、`interior<seed>-standard`：采用公开规则的标准事件数值（例如爆炸80、幻术50Tick、堡垒50Tick/驻留10Tick），保留所选测试地图和练习公告日程。原练习配置的较弱数值不再冒充标准数值；这个变体也不代表正式未知日程。参数只由测试裁判用于生成自然语言公告，不直接输入选手。
- `*-blast`、`*-blast-long`、`*-blast-early`：仅按地图边界生成的大范围爆炸压力场，前两者在Tick1公告、延后9/14Tick生效，early在Tick0公告、延后10Tick生效；只有一个事件，强度80。提前量是显式测试条件，不代表正式日程；全部场次与退步必须保留。
- `*-fortress`、`*-fortress-long`：只有一个标准强度堡垒，Tick1公告、分别延后12/40Tick生效，持续50Tick、驻留10Tick。矩形为按地图尺寸生成的中心3×3区域，不依赖任何车的轨迹。用于补足提前等待及驻留成本的机制覆盖，不代表正式事件位置或日程。

| `event_unavoidable_cost` | `false` | 仅随event_escape实验：从路径比较扣除所有乐观可达格均必承受的损伤下界，实际伤害不变；只有规则测试，尚无比赛证据 |
| `use_event_interpretation` | `true` | 对照：false时仍真实调用AI、校验与保留事件上下文，只在动作选择中不采用解释；用于区分调用资格与解释收益，不等于官方资格已验证 |
| `event_escape` | `false` | 实验：对未来32Tick内已解析的爆炸/分裂累计伤害，按时间倒推可行逃生路径，仅对预计致死结果强保留避险余量，在每个当前候选动作后保留避险余量；只用本车记忆墙和已解析事件，未来占用仍有不确定性 |
| `validated_enemy_memory` | `false` | 实验：后续本车存活视野覆盖旧敌人位置时，停止据该位置追击；保留历史记录，不推断死亡或新位置 |
| `productive_escape` | `true` | 前期采集/探索的首选下一步能减小当前可见火力暴露时，计入下一Tick的脱离收益；保留即时击杀，不声称移动能躲过本Tick攻击。false恢复旧行为 |
| `ai_action_revision` | `false` | 实验：新的合法事件解释到达后，同 Tick 最多修订一次动作；重复感知重发修订后的缓存 |
| `revision_window_ms` | `350` | 从本地收到新感知起允许修订的最长时间；应小于实际 Tick 窗口并预留网络余量，范围 1–5000ms；不是裁判截止时间保证 |

参数保存于 `run.json` 和逐场汇总。不得因为某张图变好就推广参数；需检查配对地图的严格第一率及资源变化。移动倍率、精确后续路径和伤害折扣未提高整体第一率，维持旧值。关闭早期主动拦截在多批配对中保持第一数，并改善部分基础得分，已成为新默认；动态占用路径在同一冻结程序的 24 对地图席位中仅一场提高 2.5 分、未新增第一，现作为默认路径修正；显式设为 false 可复现旧行为。这些调整仍未证明跨地图稳定第一，具体冻结版本与退步案例见 `VALIDATION.md`。

日志的`goal_reason`记录即时攻防覆盖之前的实际目标类型，`reason`仍描述最终动作选择。因此防御时也能区分资源、任务或堡垒目标；新字段只是本车规划诊断，不增加输入。跨实验综合结论、分项得分复算及未触发机制的覆盖限制见[EXPERIMENT_SYNTHESIS.md](EXPERIMENT_SYNTHESIS.md)。
