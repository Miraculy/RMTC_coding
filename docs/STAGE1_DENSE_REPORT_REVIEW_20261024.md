## 对代码的核查

1. `World.resources`已经维护本车见过且尚未证实消失的资源。seed20261024终局仍known_resources=5，恰为漏采5普通。因此应修路线选择，不需要新建重复的seen_resources来解释“忘记”。
2. `resource_options`和三站前瞻仅stage2启用。stage1是单目标资源/探索的reward/(cost+1)^0.85比较，没有在剩余预算里决定资源访问序列。
3. 起点到目标使用已知墙的加权路径，不是完全没有避障；未知格额外0.35成本。三站后两段默认曼哈顿是stage2的事实，不能当作stage1已经存在的错误实现。新一阶段的多站搜索才需要补资源间BFS。
4. `confidence=exp(-max(0,tick-seen-8)/60)`目前也用于stage1。单车、无事件、不刷新的已知资源离开视野后仅因时间流逝就被降值，与这个场景不匹配。
5. 探索与资源共用启发式比较，缺少保全已知资源路线的预算约束。seed13开局Tick0已知1个、Tick8已知6个资源，但前11Tick全选explore；Tick11/12追资源，13/14又切探索，直到23才首次采集。这不是开局没有发现资源。
6. 已存在“当前目标剩余时间不可达”过滤，因此“没有末端不可达过滤”不准确。问题更早：缺少对所有目标整体预算的预留，到了末端再过滤已无法追回。

## 建议落实的算法顺序

1. 阶段一专用的预算多资源路线规划：已知资源间用本车记忆障碍BFS，最多16资源下做子集DP或受限搜索；首要最大化剩余100−tick内可收R，同R优先更短路线。每Tick只执行合法首步，发现墙/新资源后滚动更新。未知墙不能当作真值或读取测试配置补齐。
2. 一阶段已知资源不因离开视野而按时间衰减。资源记忆的删除仍由本车合法观察/自身采集确认。
3. 给探索提供有预算的剩余机会比较：保留可兑现资源序列；探索绕路需考虑可放弃已知收益。保留必要探索，不能全局禁止探索或按资源坐标/种子写特例。
4. 精确剩余步数与顺路资源收集，优先修开局访问顺序，然后处理末端；不要仅在Tick70硬切贪心回收。
5. 用用户15图固定配置配对，独立新种子验证，加入30%/35%障碍检查；所有100Tick完整、零非法/回执异常、P95远小于100ms、阶段二行为保持。验收同时看可满分图实际满分数、各图距离全知上界的缺口、均分、单图退步、普通/高值采集。

用户提出100Tick一阶段满分，工作应继续朝可满分地图的满分路径推进。现有7图自身不具备100动作全收集路线，不能承诺任意≥25%障碍地图都满分，也不能改裁判/时长或偷用全图来制造满分。此分析不代表算法改进已完成，后续实现与成绩须另记。
