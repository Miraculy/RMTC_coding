## 6. 本轮新增发现（区别于原 11 项、六方向及团队补充）

### 6.1 默认来火仍包含同 Tick 事件先击毁的敌人

**证据：** `C:1193` 只有 forecast 开启才剔除事件致死敌车；`C:1438` 防御侧相同。但默认启用的 score_aware 攻击目标已在 `C:1448` 剔除该敌车，两个方向不一致。规则 §5.2 步骤1/2先处理事件死亡，步骤4时该敌车不能开火。

**复现：** `$AUDIT/probes.cpp` 直接链接未改动的 `librmtc_core.a`。本车(8,8)，敌人(10,8)/HP20，普通资源(9,8)，本Tick已解析的80伤害爆炸仅覆盖敌人格；本车HP分别10/20/40/60。四例默认均 DEFEND；仅在探针副本中移除已知会先阵亡的敌人后均 MOVE right。原World与参赛程序未修改，输出存 `$AUDIT/probes.jsonl`。

**影响：** 确定的本Tick事件结算可能造成无效防御和移动目标受抑，而非对手未来动作不确定性。只证明规则场景下动作差异，未证明整场可追回多少分；本轮无事件配对也不覆盖它。

**建议：P1。** 建立只用于当前Tick候选计算的 post-event 存活/占位集合，攻击、来火、防御、即时收尾、移动占位统一引用。特别区分世界分裂立即复活且强制WAIT的车辆，不能简单把它永久删除。回归覆盖爆炸非致死/保护免疫、多敌和分裂回出生点；不靠全面开启forecast修复。

### 6.2 exact_geometry 兼容路径不能完整保证请求版本一致性

**证据：** `A:81` 在入队时固定 known_events；`C:212–225` 的显式引用校验严格。但 `C:251–256` 仅在请求里找到了同ID时检查revision，**找不到时照样递增并覆盖**。这比“旧默认会保留两个几何版本”的问题更具体，是新版本保护的覆盖边界。

**复现：** 保存空known_events快照；添加同几何爆炸damage80，显式修订为20/revision1；再用原空快照提交不带ID的同几何damage80，merge接受且改为80/revision2，记录identity_basis=exact_geometry。见 `probes.jsonl` 的 `snapshot_without_identity_overwrites`。没有伪装真实模型调用或整场比赛。

**影响：** 入队时未知身份的旧请求可覆盖较新的参数/结束时间。不能再无条件宣称“所有更新均验证请求已知当前版本”；显式ID路径和原子回滚测试仍成立。

**建议：P1，启用event_revisions前完成。** 对request快照不含目标身份的同几何更新，记录明确冲突并选择可审计的保守处理；不能仅凭相同几何自动获得覆盖权限。兼容路径要增加“缺ID但请求见过旧版本/没见过ID/排队后新建/新参数相同无变化”的本地HTTP及merge测试，不能为通过而删旧测试。

### 6.3 现有同 Tick 修订 ROS 回归已失去当前默认策略前提

**证据：** `tools/action_revision_wire_test.py:115` 写死初始动作为attack；现源码无覆盖的fixture首帧实际MOVE down。在沙盒副本原样执行脚本，退出1；失败位于begin('within')，尚未放行模型结果或检查revision。进程退出及清理已执行，日志保留 `$AUDIT/action-revision-wire.log` 和 `$AUDIT/workspace/test-results/action-revision-wire-*/`。

**影响：** “132 GTest全绿”不能替代node层同Tick/换场/迟到测试；历史六项通过也不能自动沿用到当前源码。失败本身不证明修订功能坏了，亦不能忽略。

**建议：P0 验证设施。** 下一实施轮用明确且仍能产生实质动作改变的确定性fixture，验证修订前后、一次上限、缓存重发、迟到/退役/终场隔离；先独立说明初始动作为什么必选。不能简单放宽断言或改成任意move以“全绿”，也不把整套旧策略关闭来冒充默认回归。本轮遵守只读边界，未改脚本。

### 6.4 “零回执异常”的现工具口径未包含方向和最后动作

**证据：** `tools/compare_eval.py:62–77` 只对decision 1–499中的回执检查tick和动作类型；`submitted`只存action字符串，未比较move的effective_direction；`N:214` 的final日志不含last_action。因此动作499的执行回执不在该循环中。此处是验收覆盖缺口，区别于原P2-4“规划未使用error”。

**影响：** 即便工具输出零，也不能单凭它证明所有500次动作的执行方向和终场回执正确。含幻术时还必须按合法已知效果或实际位置核对，不能直接要求命令等于effective_direction。

**本轮处理：** 不改工具；独立审计补读测试端赛后`checks[本席位]`的最终公开回执，逐车核对499，且在本轮无事件组核对全部成功移动方向/位置增量。该数据只供测试驱动，不作为选手输入。结果见第7节。

**建议：P1 验证设施。** 把最终回执、完整动作元组和规则允许的强制WAIT说明纳入工具，未知或缺回执必须明确失败，不能将“报告差异但不拒绝”误当通过。

### 6.5 首次在分裂期间见到的墙，其来源仍有歧义

**证据：** `C:350` 对first≥split.start且last<split.end的记忆障碍，在事件结束后视为不阻挡；T:292只覆盖“事件前已见原墙”和“事件中临墙”两个类别，没有覆盖“原有静态墙首次在事件中被看到”。探针中仍有一份`obstacles`记忆，blocked15=true、blocked20=false。

**判定：** 这是不确定地图建模风险，不能凭探针断言该格一定是静态墙或实战必撞墙；合法观测本身无法区分叠加来源。与原先“资源记忆过期门控”无关。

**建议：P2。** 记录静态已证实/事件覆盖/来源未知；事件结束后来源未知可当待验证通路假设，但不能表述为确定已清障。先诊断这类路线是否真影响机会，再决定成本与复验策略。

### 8.1 单元与规则场景

每次只实现一个机制，独立开关和回退，先跑118 core/14 HTTP及node本地回归；新增测试是有独立外部规则预期的场景，不照抄实现断言。重点：

- 任务：D阈值前后、同Tick击杀+死亡扣60、阵亡不结算任务、已完成ID不撤销；无任务场景原行为保持。
- purity：本车防御、敌HP20/21、保护、pan、多人去重分奖、无双多目标逐个反伤；不能把预测攻击当已知。
- pepper：踩点成功/失败、脚下生成、移走敌人、双触发互伤、战斗先死不重复分奖、步骤6死则资源/reach失效。
- 事件：爆炸杀敌后不计来火，保护免疫、分裂立即复活/强制WAIT/占位；显式revision和exact_geometry的已知/未知/过期快照、批次失败回滚。
- angel：原地不触发、相邻入点、生效/结束边界、已有效果、不为刷新放弃更高可兑现目标。
- ROS：首帧前公告、只perception任务、换场旧retained、重复/过期帧、重启、同Tick修订及final不再发动作。

### 8.2 完整比赛

1. 同一冻结可执行程序，至少 **4图×4席位=16对=32场**；本车候选对3个固定独立对手，其余车参数完全相同；不同对手类型另做自己的16对，不能混算第一率。保留未调参地图，重复场不增加独立地图数。
2. 4车都必须完整覆盖动作Tick0–499，核对最终感知500、最后执行499；0非法、0感知拒绝、0未解释回执Tick/类型/成功移动方向异常，缺回执直接失败。E_BLOCKED允许但单列；分裂强制WAIT有具体规则证据才解释，不把原始差异抹成0。
3. 比较R、D、已完成/获资格任务、总分、严格第一、平均名次和全部掉分/掉名次；同时报告eligible/proposal/实际改变/可兑现机会。D增长超封顶不冒充加分；同分掉名次也算退步。
4. 加速无事件组仅用于策略配对；阶段一恢复100ms/100Tick、阶段二500ms/500Tick完成默认节奏联调。本轮已另做这两类验证，但未做付费事件资格验证。
5. 新机制有效才推广。任何默认改变需无参数入口回归及新图/对手验证；本轮16对并不自动满足多对手和正式网关门槛。

### 8.3 真实模型验收（本轮禁止，后续须显式授权）

双方都通过真实练习代理调用模型，仅隔离待测参数或解释采用。逐级分别记录：**调用成功 → 结构接受 → 语义正确 → 生效前可用 → 实际动作改变 → 全场分项/名次收益**。核对焦点席位调用数，不将其他车调用计成本车；先比较每车首次动作差异，识别对手更早分歧的混杂。

正式反馈在公告后、生效前返回是用户给定条件，不是假设固定提前量，更不保证模型语义正确。练习迟到不能用来否定按时条件下的策略；合成预置结构只验证本地结算，不冒充LLM理解。只有主办方正式本场席位成功审计才能证明任务计分资格，任何练习HTTP200均不能替代。

## 9. 风险与未解问题

- **版本漂移和证据迁移缺口：** 旧二进制、源码manifest、原比赛/模型日志未提供；本文只能为当前源码建立新基线，不能认证历史9945/6332的完整关系。建议下轮归档源码树指纹、冻结程序、编译参数、依赖、实际配置及必要原始本车日志，区分独立测试与复算摘要。
- **正式网关尚未验证：** 本轮零付费调用，AI资格未新增任何证据；本地HTTPfixture和练习任务分不等于正式资格。默认模型、输出限制、席位令牌和现场有线DDS仍待官方联调。
- **样本外推：** 四图同一默认对手、无事件、加速组不是跨图稳定第一，也不是事件条件下收益；四个席位相关，不能当16张独立地图。基准stage1满分只说明那一图已采尽。
- **关闭实验不等于完成优化：** event/purity/opening代码存在不等于收益成立；反之四对同动作未覆盖关键纠错机会也不能证明无价值。必须区分未触发、触发但被覆盖、动作改变但无收益、最终退步。
- **旧负结果仍然约束下一步：** 信息路径、竞争探索、延后追击、任务优先、安全首步/复活路线、过度避险均有文档退步；本机缺原档，不重新混算，但没有证据可把它们悄悄当作成功策略重开。
- **状态推断限制：** 未见高值不代表高值不存在，资源消失不能证明完整对手分数；未知墙/未来占位/精确复活点不可当真值；事件几何/效果输出即便结构合法也可能错误。
