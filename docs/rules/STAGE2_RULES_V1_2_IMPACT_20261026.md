# RMTC v1.2规则对第二阶段当前策略的实际影响

日期：2026-10-26  
范围：对比v1.1与v1.2赛事规则，分析第二阶段策略影响。  
状态：规则分析文档；未审查源码、未修改策略、未进行比赛测试。

## 1. 结论

v1.2不要求重写当前第二阶段的计分目标和基本攻防策略。最直接的战术影响是：**天下无双的堡垒区域不能固定为地图中心或固定坐标，必须服从本场公告。**

新增的复活落点说明与此前用户提供的补充一致，属于正式明确规则：继续以当前感知的实际位置恢复决策，不把出生点当成必然复活点。

因此，当前“前期争夺资源和高价值资源、争取完成任务，再根据资源与伤害封顶、死亡风险和同分竞争调整行动”的方向仍然成立。需要重点检查的是事件几何信息、堡垒收益评估和复活后的重新规划。

本文件中的“当前策略”依据此前会话已经确认的策略方向描述，**不代表已经核实当前仓库的每一处实现均符合v1.2**。

## 3. 天下无双：实际区域必须优先于固定中心

### 3.1 新增条文的含义

v1.2在§8.5补充：堡垒多数位于(11,11)–(13,13)的3×3范围，但部分地图存在特殊变化，以赛时自然语言公告与话题为准。

这意味着“多数位置”只能用于理解规则，不能作为每场比赛的确定坐标。以下实现假设都需要在后续源码审查时排除：

- 无双事件一出现，就把目标设为地图中心。
- 固定使用(11,11)–(13,13)，覆盖公告给出的不同区域。
- 模型未返回区域或返回结果未通过校验时，擅自补成中心堡垒。
- 更换地图后，沿用上一场堡垒坐标或事件时间。

### 3.2 对当前决策流程的影响

应继续采用已有的“LLM理解公告、本地程序校验并规划”的方式：

1. 从合法公开公告获取事件信息，由官方AI服务理解区域、时间和效果。
2. 校验模型返回的区域与时间，确认属于当前场次及当前有效事件。
3. 按实际区域估计到达时间、可完成的驻留时间和获得增益后的有效行动窗口。
4. 比较争夺堡垒与继续采集、完成任务或其他合法行动的预期最终收益。
5. 行动过程中根据新感知重新判断生存条件和路线可行性。

区域未确认时，继续执行已有资源或任务计划；不根据观赛全图、关键词模板或固定中心坐标补充事件真值。

### 3.3 哪些堡垒机制保持不变

以下为规则标准配置，具体场次仍遵循有效官方公告：

| 项目 | 机制 | 对策略的要求 |
|---|---|---|
| 存在时间 | 50 Tick | 到达、驻留和后续获利共享这段事件时间 |
| 驻留门槛 | 连续10 Tick | 需要在每次战斗后存活且移动后处于区域内；离开或死亡会清除未完成进度 |
| 获得增益的时序 | 达标Tick的战斗后授予 | 本Tick已经结算的攻击不能追溯变成无双攻击 |
| 攻击方式 | 主动提交ATTACK及合法方向 | 不会自动攻击；方向不限制无双的目标集合 |
| 攻击范围 | 自身横纵各±2的5×5方形，含斜向，不受障碍遮挡 | 应按方形范围评估可见目标与威胁 |
| 伤害 | 非防御目标50HP、防御目标10HP、出生保护目标0HP | 不应把无双防御伤害按普通比例推算 |
| 增益保留 | 可离开堡垒，跨死亡复活保留 | 达标后不必继续守在堡垒内；死亡仍有伤害扣除和时间损失 |
| 增益结束 | 堡垒结束时统一失效 | 不能按个人达标或复活时刻重新计算完整持续时间 |

### 3.4 “能达标”不等于“值得去”

以下是按§5.2及§8.5时序作出的规则推导例：

假设堡垒在Tick100生效、Tick150失效，其他条件均满足，且车辆进入后连续存活并驻留：

- 在Tick135的移动结算后进入：135–144累计10次，在144战斗后获得增益；最早在145使用，至149共有5个攻击窗口。
- 在Tick140的移动结算后进入：140–149可累计10次，但增益在149战斗后才授予；下一次攻击窗口150时事件已到期，因此没有可用的无双攻击窗口。

这说明堡垒选择必须评价“到达后还能实际利用多久”，不能只检查是否来得及凑够10次驻留。即使还有攻击窗口，如果附近没有可攻击目标、到达过程容易阵亡，或者会错过高价值资源与任务，也可能不值得争夺。

评估应使用最终计分和合法已知信息。D已满500时，无双新增伤害未必增加对抗分，但可能提供死亡储备、同分优势或合法竞争收益；这些不能被当作固定的额外比赛分。

## 4. 复活：确定选点规则，不等于提前知道落点

### 4.1 v1.2正式明确的规则

以车辆初始出生点为基准，按曼哈顿距离从近到远分层搜索；同距离按上、右、下、左的优先顺序逐层确定首个合法格。

合法落点需要在地图内，没有静态障碍或生效中的分裂墙，且没有其他存活车辆占用。资源格可以复活。障碍只排除落点，不阻断选点搜索。多车同时复活发生落点竞争时，按A→B→C→D依次处理，先复活者占用其落点。

这与此前用户提供的补充一致。等待与保护规则没有因此改动：普通死亡当Tick不递减等待，随后3次Tick结算递减；普通复活有2 Tick出生保护；世界分裂是立即复活的特殊情况。成功移动后若不在初始出生点，出生保护立即取消。

### 4.2 对当前二阶段策略的影响

| 策略环节 | 必须避免的假设 | 建议处理 |
|---|---|---|
| 本车死亡后恢复 | 一定回到初始出生点 | 以新感知self.position为准，重新评估资源、任务和威胁 |
| 追击或守出生点 | 占住一个格就能保证对方无法复活，或保证下一次攻击命中 | 对手可能转移到其他合法落点；未来占位未知时只作可能性预测 |
| 复活选点模拟 | 用普通BFS的路径可达性限制候选落点 | 按距离与优先顺序枚举，障碍只检查落点合法性 |
| 资源处理 | 资源格不能复活 | 资源存在本身不排除落点；资源状态仍以合法感知及结算为准 |
| 多车同时复活 | 所有车辆可各自独立选到同一格 | 在信息足够的模拟中按席位顺序更新占位 |
| 出生保护 | 复活后无论怎样移动都能保留完整保护时间 | 按实际保护状态及移动后的规则判断，不能在保护中提交ATTACK |

即使规则是确定性的，车辆对隐藏障碍、其他车当前位置及未来占位的知识也可能不完整。因此，本车实际复活坐标应直接读取；对手未被观察到时，不能把预测落点写成实时真值。

## 5. 核心计分未变，当前主策略继续成立

依据v1.2第18–19页、§10.1–10.2：

| 指标 | 规定 | 对当前策略的含义 |
|---|---|---|
| 资源分 | 30×min(R/120,1) | 资源与高价值资源的早期争夺仍是主要得分机会；达到120R后继续采集要比较其他机会 |
| 对抗分 | 15×min(D/500,1) | 保持边际收益核算；D=500不是永久满分，死亡会让D下降 |
| 任务分 | 每项5分，三项最高15分 | 按本场实际公布任务规划，不能把练习任务或练习坐标当成正式固定内容 |
| 击杀奖励 | 每个被击毁目标总量60，合格贡献者去重分配 | 保留实际伤害、过量伤害分摊和击杀贡献核算 |
| 死亡扣除 | 每次死亡扣60D，最低0 | 生存、复活等待和死亡后的机会损失仍要计入战斗选择 |
| 同分排名 | 总分、获计分任务数、资源总值、D、无效动作数依次比较 | 超过计分封顶的资源和D仍可能用于同分比较；D不在500截断 |
| AI资格 | 每场、本席位至少一次真实统一AI成功调用，否则任务计分数M=0 | 继续保障本场调用成功；其他场次或练习调用不能替代 |

原有资源争夺、任务完成、伤害封顶与储备、同分竞争、主动防守和合法事件利用，不需要因为v1.2整体推翻。堡垒应作为与这些目标竞争的一个机会，而不是固定的最高优先级。

## 6. 交付要求变化

这些变化影响上场准备，不直接改变战术：

- 正文明确语言不限，推荐C++17及以上；更新日志中的“语言限制”不能理解成强制改用C++。
- 材料递交项由代码、镜像、报告改为代码仓库与技术报告。
- 报告补充AI协同开发、测试截图、代码运行逻辑及运行指令等内容。
- 提交代码应完整可运行，提交的路径及版本应与比赛实际启动的一致。

对存在多个实验版本的项目，应明确哪一个版本和启动命令用于正式比赛，避免报告描述、提交版本和实际入口互不一致。测试截图也应对应所描述的程序与真实记录。

| 优先级 | 检查内容 | 判断标准 |
|---|---|---|
| 高 | 堡垒区域与事件缓存 | 公告区域优先；没有覆盖公告的固定中心回退；不跨场沿用 |
| 高 | 堡垒到达、驻留、增益生效与结束时序 | 比较实际可利用窗口，避免仅来得及达标却无法攻击 |

| 中 | 多车复活与出生保护 | 席位顺序只在信息足够时使用；移动取消保护与禁止攻击规则一致 |
| 中 | 正式交付说明 | 唯一明确的正式入口、版本、依赖及可复现运行说明 |
