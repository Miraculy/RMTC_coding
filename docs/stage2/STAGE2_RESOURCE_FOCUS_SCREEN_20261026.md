# 新鲜资源机会与探索保持：实现及筛查

本轮在v1.2堡垒位置补充核验后，继续原资源优化任务。该方案基于完整17af二阶段源码，独立于已否决的7bcd回收机会探索。

## 思路与实现

原控制器对保持中的探索目标乘1.5，即使已经出现可见资源。候选新增默认关闭的`resource_opportunity_focus`：二阶段前100Tick、R<120、无已解析事件且未组合其他实验探索模块时，若存在本Tick看见、已观察空地上2倍视野半径内可达、未被当前车辆占据且近期已见活对手没有乐观先到机会的资源，则取消旧探索目标1.5倍保持奖励，改为1。其他资源收益、目标和即时攻防比较保持原式。

候选没有强制资源优先，不修改资源真值，不以公平推断隐藏坐标，不保证隐藏敌人或战斗不会阻止采集。所有条件及触发记录可以从本车日志审计。

## 测试与预登记筛查

- 独立Release构建通过；139项核心测试（136旧+3新）、14项HTTP测试通过，两个CTest目标通过。
- 新测试覆盖保持奖励解除、只用已观察通路、可见先到对手排除、对手记忆过期、阶段/封顶/时间/事件回退以及死亡/重置清理。
- 使用上一轮24份合格B1本车历史，每个版本12,000帧。新程序关新开关的动作/目标/原因全部复现B1。
- 开启候选后，仅value62002-D的4帧动作变化，首次Tick36；count61001-A有目标/原因变化但整场动作不变。公平16组仅1组出现动作变化。

在保持原确定性场景和对手的条件下，未出现首个动作分歧的配对不能产生策略导致的资源增量。因此该候选最多只能影响1/16公平案例，不可能达到预登记“至少60%配对提高资源”所需的至少10组。本轮在重放筛查阶段否决，**没有为此新增裁判比赛，没有测得资源增益，也不把4次动作变化当作增分**。这是一项候选覆盖面筛查，不是跨分布不可能性证明。

源码：`experiments/stage2-resource-focus-20261026/src`；计划：`PLAN.md`；结果：`results/replay-summary.json`、`results/replay-screen.json`。冻结程序SHA256：`da46b2dd2756644584d80ec298c4ac8b08a690e066cfe8ba31d0b23f4e86548c`。

后续继续检查已有竞争到达时间选项；不把已有BFS/ETA实现包装成新功能，也不将重放结果冒充比赛。正式安装17af和一阶段源码未修改。

## 既有竞争到达时间开关的续查

进一步只打开既有`race_aware_resources`，保留B1的恢复开关，不打开新focus。该能力原本就有已知墙BFS、最近对手位置、运动方向启发和后续站点到达折扣，本轮没有重复宣称为新实现。

同一24份本车历史、12,000帧中共25帧动作变化；公平组仅count61001-A/D、value62001-A、value62002-D四组出现动作变化，首次分别为24、27、23、40。其余12个公平案例没有首个动作分歧，因而单独开启该选项也不能在此确定性集合达到至少10组改善的预登记门槛。没有为该选项新增实战，未测得资源收益，不做推广。结果为`results/race-replay-summary.json`及`results/race-replay-screen.json`。

该结论只针对单项开关及冻结参数，没有测试所有交互组合，不能据此否定竞争建模本身。后续应针对前期访问次序与实际采集机会提出更有覆盖面的假设，再进行闭环测试。
