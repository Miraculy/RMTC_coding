# 二阶段参赛代码竞争力与优化方向分析

日期：2026-10-27。范围：复核既有报告、修改历史及完整二阶段源码。本轮没有运行测试、重放、模拟、比赛或模型调用，没有修改参赛代码、默认参数与安装程序。下文的测试数字均为历史结果；优化建议是待验证假设。

## 1. 总体判断

**现有代码有取得局部优势的实质能力，工程执行和部分攻防机制已有较充分证据；但现有数据不足以证明它在不同地图、不同强对手面前具有稳定的名次优势。资源竞争仍是最明显的短板，战斗、任务与路线之间的机会成本也是重要缺口。**

如果问题是“能否利用某些对手的弱点或事件机会赢下一场”，答案是能，历史中有完整配对证据。如果问题是“能否在绝大部分公平地图上明显多拿资源，或者稳定进入前二”，目前还不能肯定。没有独立强队对手池及正式网关条件下的完整验证，无法给出可靠的正式赛胜率或晋级概率。

从修改历史看，最明确的收益来自解除特定战斗僵局、追击循环，以及正确利用提前解释的事件。多次资源实验没有形成相同强度的通用收益。失败实验被关闭，保护了默认策略，但关闭本身不构成算法能力提升。

## 4. 为什么尚不能判断有稳定的竞争优势

### 4.1 自己多得分，不一定更容易赢

现有最有价值的跨版本总对照，是早期兼容版本1300b2与9945在四张新图、固定三种异质对手下的16组配对：

| 指标 | 早期版 | 当时当前版 |
|---|---:|---:|
| 平均总分 | 38.41875 | 40.3125 |
| 平均资源R | 49.375 | 50 |
| 战斗分达到封顶 | 12/16 | 16/16 |
| 三任务全部完成 | 9/16 | 9/16 |
| 严格第一 | 4/16 | 3/16 |
| 平均名次，越低越好 | 2.4375 | 2.5 |

平均增分约75.25%来自战斗，资源仅贡献约8.25%。这说明历史修改确实提高了某些得分能力，但未形成同等幅度的排名收益。

map62573-D尤其典型：本车41.4→45分，却从第一变第二；固定程序的B车因对局变化从36.1→47.5分。自己的行动会改变对手的收益，不能只用本车D是否封顶来判断战术价值。

同场四种配置的成绩也没有显示当前默认版全面领先。不过这些配置仍属同一规划器家族，四轮只平衡出生席位，没有覆盖全部相对邻位，因此既不能认定默认版最强，也不能直接把表中均分最高的配置换成正式版。

### 4.2 资源接近公平份额，限制了进一步拉开比分

在现有200R配置下，四车均分为50R；公平组52.5R对应全池约26.25%，只略高于四等分。公平意味着各出生区域数量或价值接近，不意味着等距离、资源坐标可推断，也不意味着单车能够稳定取得120R。

按现有计分，若本车R=50，即使战斗15分和任务15分均拿满，总分也只有42.5。多一份10R普通资源可增加2.5资源分；多一份20R高值资源可增加5资源分，若同时完成尚未完成的任务，还可能另有任务收益。**在战斗已较容易封顶的对手池中，额外资源和任务兑现对拉开差距的价值会更突出。**

这不是说50R是策略上限，也不是要求每局都追120R。120R占200R全池的60%，应作为有利局面的进取结果，而不是所有席位的基本合格线。

### 4.3 多次失败指向全程访问顺序和收益估计

历史资源实验有三类共同现象：

- **改变得太少。** 精确资源间路径在24份历史中没有动作变化；新focus仅影响1/16公平案例，既有竞争到达开关仅影响4/16。单项修正覆盖不到多数资源机会。
- **改变路线但丢失后续资源。** 回收机会探索公平组52.5→50R，1增、11平、4降；一个案例多10R，另一个少20R。后者改变早期方向后，整场未见旧路线最终采到的两份资源。
- **局部行为看起来改善，终局并未改善。** 更早完成任务、更少往返、更多视野、局部风险更低，都出现过最终不增分或退步的结果。

因此，现阶段继续增加一个探索权重、延长搜索深度或直接开启旧开关，缺少足够理由。下一步需要解释：新选择会保留哪些原有收益、赶上哪些额外机会，以及为何不会因路线和对手响应而失去更多。

## 5. 值得优化的方向与优先级

以下“证据强弱”指问题定位的可信程度，不代表新方案已经有效。

| 方向 | 问题证据 | 预期作用 | 当前建议 |
|---|---|---|---|
| 前期资源与观测路线的访问顺序 | 强：资源迅速分完、发现太晚、探索改道丢资源 | 改善资源份额，覆盖面和潜在收益较大 | 资源专项首选；需要形成完整路线方案 |
| 僵持交战的任务与阵亡机会成本 | 强：两个反例对单模块消融敏感 | 减少丢任务、掉名次，保留原有战斗优势 | 总分/排名专项首选；适合先做局部保护 |
| 到达时的可采集性与失败反馈 | 强：真实争格失败存在；泛化收益证据弱 | 避免追逐实际进入机会低的资源 | 纳入路线估值，避免重复开发已有ETA |
| 事件从解释到收益的时间窗口 | 强：既有成功与无收益案例并存 | 把已有事件理解能力更稳定地兑现 | 保留现有架构，先处理明确时序缺口 |
| 正式源码、安装程序和配置的对应关系 | 强：根源码与当前二阶段安装来源不同 | 防止交付与复编丢失已验证能力 | 发布前必须明确，不能算算法增分 |

### 5.1 资源专项首选：按可兑现收益比较完整的短路线

既有异质16场中，全池到Tick20平均已收75.625%，Tick40已收96.5625%。最新公平16份本车历史累计见到1140R、采到840R，差额300R中160R在首次看见时，按乐观步行距离也赶不上后来观察到的消失；120R只是可能需要更早发现或更好选择的候选机会，尚未证明可追回。另有3场高值任务失败且始终没有看见高值资源。

这些证据把优先级指向**早期往哪里走、以什么顺序访问**。0–20/40Tick是诊断上的主要窗口，不应写成统一阶段截止线。

建议把“继续当前已知资源链”“调整资源访问顺序”“经过一个观测点后再取资源”放在同一短路线比较中。每条路线都同时考虑到达时间、当前可兑现资源、尚未完成任务的边际分、观测后可能回收的机会，以及为了探索放弃或延迟的资源。当前已有三站前瞻、BFS选项和beam实验，新增价值应来自这些估值与后续分支的衔接，而非再次实现搜索名字。

实现设计应保留完整的基线控制器记忆作为比较参考，明确对手动作和未知地形只是假设；允许有收益依据的有限冒险，不要求每个场景严格不退步。已知路线也可能被竞争或交战打断，不能把它称为无条件收益保证。

公平条件可用于研究开局覆盖是否偏离本车周边机会，但不能推断“本区必有50R剩余”、隐藏出生区边界或资源坐标。只提高中心探索优先级，也不能由堡垒位置补充推出。

**这里的目标是更早发现并取得仍有竞争机会的资源，同时保住普通资源链；新看到多少格只能作为诊断。** 对未来候选应看最终R、高值任务率及总分/名次，不能把预测收益当实际收益。

来源：[资源窗口复盘](../research/RESOURCE_BOTTLENECK_REFLECTION_20261024.md)、[公平机会分类](STAGE2_FAIR_RESOURCE_REVIEW_20261026.md)。

### 5.2 总分与排名首选：给僵持开火补上后续机会成本

当前`standoff_robust_trade`不是盲目开火：它限制低HP、可见单敌、特定稳定僵持或可收尾条件，并比较对方攻击、防御、等待/移动的局部结果。其历史防御对手组收益明确，应保留。

缺口是，局部战斗分在各分支都增加，仍可能因阵亡、赶路中断而损失后续任务，或者让交战对手获得更大的竞争收益。源码也明确承认复活仍会损失未来机会。

已有两个事后诊断支持优先检查触发边界：

- interior59341-A：当前27.9分、1任务；仅关闭该模块为42.5分、2任务。
- map62573-D：当前45分、第二；仅关闭该模块为41.4分、第一。

这两个案例不支持全局关闭模块，却给出了因果链较短的优化入口：开火前加入本车尚未完成任务、剩余时间、合法已知路线以及可能阵亡后的机会损失。对未来复活位置保持不确定，实际复活后再用当前感知修正规划。

还应根据合法可见交战信息，估计这一动作是否在向敌方提供伤害/击杀机会；对手隐藏D、资源和任务不能当作已知，也不能按赛后名次在线触发。目标是改进竞争决策，不是凭空计算一个精确胜率。

已有`score_aware_combat`、D封顶、死亡储备和末期同分价值都应继续纳入。D达到500后仍可能因死亡扣减，不能简单规定“到500就永远不打”。更有针对性的方案是限制高机会成本交战，按剩余风险调整储备，而不是只追伤害或只追存活。

来源：[异质反例及单模块消融](../research/HETEROGENEOUS_BENCHMARK_20261024.md)；源码位置：`baseline/src/rmtc_bot/src/core.cpp`约1372、1589、1770–1850行，`baseline`相对实验目录`experiments/stage2-fair-20261025`。

### 5.3 将竞争与失败反馈纳入路线，而非独立叠加折扣

默认资源估值中有年龄衰减、近期敌人更近时0.4折扣、早期回头资源0.6折扣；探索目标保持奖励为1.5。它们都是启发规则，组合后的数值不等于经过校准的实际采集概率。

可选竞争模块已有敌人路径下界、观测年龄和运动方向估计，但对手可能停下攻击、防御或改道；同一敌人也不能同时奔向所有资源。更值得研究的是用少量互斥的对手行动/目标分支比较整条候选路线，分别计算封顶、任务和失败后的备选，减少对同一种风险反复折扣。看不到的敌人仍保持未知。

失败回执恢复提供了局部正例：主组16对仅一对R50→70，其余15对不变；新图8对不变，最新公平复评没有有效启动。它说明反馈值得利用，但不能承担普遍增资源目标。

因此更合理的定位是：保留回执驱动的可执行性检查，将它与到达估值、目标承诺期限和备选路线连接。单独开启更复杂ETA，或仅取消探索保持奖励，已有覆盖不足证据。

来源：[恢复方案及边界](../research/RESOURCE_RECOVERY_20261025.md)、[资源专项失败案例](../research/RESOURCE_OPTIMIZATION_20261024.md)、[重放覆盖筛查](STAGE2_RESOURCE_FOCUS_SCREEN_20261026.md)。

### 5.4 事件能力值得保留，优化重点在可用时间和实际价值

模型调用、结构化解释和规划解耦已经存在，节点也已实现未取得成功调用时的资格请求重试；无需再把这些当作待添加功能。优势取决于公告解释完成后是否还有时间赶到、取得效果并实际利用。

v1.2堡垒位置补充与现有实际矩形解析、缺矩形拒绝、跨场清空兼容。未独立拿到原v1.2 PDF，本次沿用用户澄清及已有核验，不扩张规则结论。

一个明确但作用范围较小的缺口是：堡垒局部驻留奖励可能奖励“本Tick刚满足驻留、下Tick已过效果结束时间”的动作。应对齐首次可用Tick与事件/比赛结束时间，再计算潜在可利用收益。它是独立边界问题，不是新位置规则造成的，也不能由此直接开启此前未证明有效的整套堡垒预算实验。

更广泛的事件优化应关注“解释及时→路线可达→效果来得及使用→资源/任务/战斗实际增分”整条链。当前正常事件场有多次无增分，不能从定向幻术正例推断普遍优势。正式AI资格仍需主办方网关确认；本地HTTP成功和练习裁判任务分不能替代它。

## 6. 对后续研究方法的建议

从历史看，工程正确性检查越来越完善，候选的收益模型却没有同步变得足够准确。后续应先说明可修复机会的覆盖面，再决定是否投入完整闭环实验。

1. **先定位，再选方案。** 已发现但放弃、发现时已太晚、到达时失败、交战打断、最终计分没有增加，分别记录。当前已有生命周期分类，后续应扩充利用，而非重新从零建设。
2. **把收益、风险和对手响应放在同一比较范围。** 资源路线和即时战斗的估值应衔接；任务阈值、资源与战斗封顶不能重复计奖。未知收益与确定观测分开保存。
3. **先看首个行动差异和机会覆盖，再看闭环结果。** 固定合法历史重放能排除几乎不改变行动的候选，但不能证明改变后的收益。多项开关的组合也不能直接相加其单项覆盖率。
4. **接受少数退步，但衡量整个目标分布。** 不要求新方案逐场严格胜过旧版；仍应同时报告改善/不变/退步比例、平均收益、严重损失及排名变化。允许退步不意味着单一已知案例修复就满足“大多数条件明显提高”。
5. **按目标区分验收。** 资源专项主看资源份额和高值任务，排名专项主看前二/第一及下尾表现；平均总分上涨不能替代两者。四图多席位不能当作大量独立地图。
6. **保存单一可复编的二阶段发布基线。** 固定源码、默认配置、构建入口与程序哈希；实验开关归档清楚。根源码和安装程序来源不同的问题，应在下一次发布前处理。

未来若恢复验证，尚缺的独立对手、相对席位排列、未见图、正式节奏和真实提前事件条件应分别补齐；本报告没有启动这些工作，也不把它们列成已经完成的验证。

## 7. 建议的下一步与本轮交付

若下一步继续以资源分为目标，优先形成“已知资源链＋一个观测分支＋竞争/失败后的备选”的完整早期访问方案，先核实机会覆盖与预测误差；不再单独微调探索奖励。

若下一步优先提高总体得分和名次，则先研究僵持开火的任务/阵亡机会成本保护。它有较清楚的反例定位，修改范围也较容易控制，但预计首先是减少特定退步，不能预先承诺大多数资源案例提高。

这两项应分方案交付，避免一次同时改资源和战斗后无法解释收益来源。堡垒时序边界可作为独立正确性修复，不能替代资源方案的成功标准。
