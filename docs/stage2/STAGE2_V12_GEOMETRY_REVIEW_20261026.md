# v1.2堡垒位置补充：实现核验

日期：2026-10-26。用户补充说明本次基本仅限定大部分地图的堡垒位置。收到的是 `rules2/STAGE2_RULES_V1_2_IMPACT_20261026.md` 规则影响分析，原v1.2 PDF未在已知目录找到；本报告按用户确认及附件明确条款核验，不声称已独立精读原PDF。

## 已确认的实现

检查的是已安装17af对应的完整二阶段基线源码，位于 `experiments/stage2-fair-20261025/baseline/src/rmtc_bot`，不是未推广的7bcd探索候选，也不是根目录一阶段版本。

- `src/ai.cpp`的模型提示要求精确堡垒矩形；信息不确定时省略，不补固定中心。
- `src/core.cpp`的`Events::merge`要求无双事件包含合法矩形，检查本场session、地图边界和时间；没有矩形会拒绝，无“默认(11,11)–(13,13)”回退。
- 堡垒目标遍历本场事件的实际矩形；不会用地图中心覆盖公告。
- `World::update`在新session清空事件、效果及旧地图记忆。实际本车复活位置读取当前感知，初始出生点另外记忆，不用出生点覆盖复活位置。

因此，“多数地图中心堡垒、特殊图服从公告”的补充与现有处理兼容，无需为此修改默认战术或把中心坐标写入程序。收到公告前也不以多数位置为确定目标。

## 定向核验

独立C++检查直接编译冻结基线core.cpp，9组通过：中心与两种非中心矩形的目标落点；缺矩形拒绝；只有自然语言而未经模型解析时不生成事件；跨场清空并拒绝旧session；实际复活位置及保护中攻击禁令；两种进入时机的增益生效/结束边界。

这是核心组件构造测试，没有真实模型调用，也不是新增赛事实测。源码、可执行检查及结果在 `experiments/stage2-rules-v12-20261026/{tools,results}`。

上一轮6图、72场均无事件，堡垒位置补充不影响这些已归档配对的机制；仍标记为现有练习裁判下的开发结果，不改称v1.2事件实战。其回收机会探索候选平均资源退步，继续保持关闭。当前资源计分、全池200R与120R封顶目标按用户补充未变，后续仍从这些失败证据选择改进，不因多数堡垒居中就提高中心探索优先级。
